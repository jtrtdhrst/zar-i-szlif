# VOICE + RULES — jak ma brzmieć treść (KANON wiki 2026-09-05)

Źródła: `wiki/synthesis/invarianty-i-brand.md` (Głos / Język / Proof / Status), `wiki/concepts/brand-dna.md`.

**Nazwa publiczna produktu: Żar i Szlif**. Zachowaj domeny i identyfikatory techniczne. „Kompas Zbiórek” to poprzednia nazwa, nie obecna marka.

## Zasady (obowiązkowe)
1. Polski, konkretnie, do jednej osoby — jak doświadczony instruktor do instruktora, bez zadęcia i bez udawania kumpla na siłę.
2. Zaczynaj od rozpoznawalnej sytuacji, potem funkcja. Pokazuj proces, nie magię.
3. AI przedstawiaj jako opcjonalny interfejs, nie decydenta. Zawsze odróżniaj plan od wykonania.
4. Konkretna korzyść zamiast pustych obietnic. Treść kończy się działaniem w drużynie.
5. Metafora terenu (azymut, trasa, cykl) tylko gdy niesie znaczenie — nigdy ozdobnik.
6. Hierarchia: tytuł niesie sens, etykiety nie konkurują z tytułem. Krótko.
7. Bez nachalnego marketingu: zero FOMO, presji czasu, wykrzykników na siłę.
8. Nie obiecuj funkcji bez CURRENT evidence. TARGET ≠ CURRENT. Onboarding = UNAPPROVED — nie komunikować.
9. Pokazuj sposób sprawdzenia twierdzenia (mechanizm krok po kroku / realny ekran), nie samo twierdzenie. Oddzielaj przykład DEMO od wyniku użytkownika.
10. Nie moralizować.

## Zakazy
- Żargon SaaS i techniczny na zewnątrz: `platforma`, `enterprise`, `game changer`, `rewolucjonizuje`, oraz `MCP / skills / tools`.
- Nachalność: `NIE PRZEGAP!`, `ostatnia szansa`, `tylko dziś`.
- Pustosłowie: `wspieramy rozwój kompetencji przyszłości`.
- Protekcjonalność (`kochani harcerze`).
- Wymyślone liczby / statystyki / opinie / procenty / liczba użytkowników / cennik.
- `sprawdzone na drużynach` bez evidence.
- Przedstawianie TARGET jako CURRENT, obietnice automatycznych idealnych rezultatów.

## Język produktu (używać dokładnie tak)
`aktywność`, `element aktywności`, `cel główny aktywności`, `plan roczny`, `cel średnioterminowy`, `sprawność`, `wymaganie sprawności`, `aspekt fizyczny / społeczny / duchowy / intelektualny`, `materiały`, `zadania przygotowawcze`, `eksperyment`, `podsumowanie`, `refleksja`, `Kontekst`, `Archiwum`, `Baza Aktywności RR`, `asystent w ChatGPT`.

## CTA (kanoniczne)
- Główne (jedno na treść): `Dodaj do ChatGPT` / `Dodaj Żar i Szlif do ChatGPT`.
- Pomocnicze: `Zobacz poradnik`.
- Edukacyjne: `Opisz aktywność. Kompas pomoże ułożyć plan krok po kroku z Twojego kontekstu.`
- Onboardingowe: NIE UŻYWAĆ do nowej decyzji produktowej (UNAPPROVED).

## Formaty
- **Post/artykuł**: sytuacja instruktora w 1–2 zdaniach → funkcja / proces → działanie do sprawdzenia → jedno CTA.
- **Email**: max-width ~600px, fallback plain-text; transakcyjny ≠ marketingowy.
- **SEO**: `asystent AI dla instruktorów Royal Rangers`, `planowanie zbiórek`, `plan roczny drużyny`, `sprawności RR`, `aktywność harcerska`, `Baza Aktywności RR`.

## Kontrola przed publikacją
Kto → problem → oferta → wiarygodność (mechanizm / ekran) → ton → następny krok + status CURRENT / TARGET / UNAPPROVED. Jeśli brak elementu — dopytaj, nie zgaduj. `npm run test:all` nie dotyczy .md, ale wymagany self-check grepa: brak `ZHR/ZHP` jako kanonu, brak `00-06 / STATE.md`, brak obietnicy problem-solving jako głównej.
