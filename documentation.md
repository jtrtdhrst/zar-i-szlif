# Dokumentacja Kompasu Zbiórek

## Produkt

Wtyczka UI (widget + Worker + serwer MCP) dla ChatGPT. Karta zbiórki jest samowystarczalnym artefaktem roboczym: dane i obecność, sprawności, eksperyment, przygotowanie, plan godzinowy, refleksja. Dane robocze w `localStorage` (szkic `kompas-zbiorek-draft-v1`).

## Stan funkcji (aktualny)

- **Cykl user-facing**: Planowanie → Realizacja → Analiza → Decyzja. Aktualne AS-IS, zatwierdzony TO-BE i DELTA: [KOMAA-48](/KOMAA/issues/KOMAA-48). Planowanie ma wyłącznie systemowe checkpointy: Cel i sprawności, Przebieg, Przygotowanie; nie są one zadaniami użytkownika. Dla etapów 2–4 nie zdefiniowano podzadań ani bramek.
- **Karta aktywności**: zakładki Planowanie, Realizacja, Analiza, Decyzja. Planowanie obejmuje cel i sprawności, przebieg oraz przygotowanie. Plan godzinowy: wiersze z godziną, aktywnością, aspektem (Fizyczny→Intelektualny→Duchowy→Społeczny→Gry i zabawy→brak), osobą, materiałami; przeliczanie kolejnych godzin; zmiana kolejności (góra/dół, drag).
- **Baza aktywności**: przycisk "Znajdź w bazie" — popup wyszukiwania; dla aspektu "Gry i zabawy" popup "Baza gier i zabaw" (proxy Workera). Wybór przepisuje nazwę, opis, czas trwania do wiersza planu.
- **Sprawności**: katalog z `sprawnosci.kompaszbiorek.pl` przez Worker; ukrywa pozycje wybrane i ukończone (grupy/poziomy); kryteria w tabeli, statusy kolorystyczne; ukończenie grupy dodaje ją do historii i jedno edytowalne zadanie `Wręcz naszywkę (Nazwa grupy) – Nazwa sprawności – Poziom` ze statusem `Do zrobienia`. Zadanie otrzymuje powiązanie z najbliższą przyszłą aktywnością planu rocznego, gdy taka istnieje; jego identyfikator źródłowy zapobiega duplikatom po zmianie statusu, renderowaniu i odświeżeniu. Nazwy zawsze jednoliniowe.
- **Eksperymenty**: osobny widok (lista + szczegóły: kontekst, zmiana, przygotowanie, próby, ocena i decyzja) oraz kafelki na karcie aktywności. Status wyliczany z danych. Lista nie może być pusta.
- **Plan roczny**: wiele planów (zakładki), temat roczny, horyzonty miesięcy z "Dodaj aktywność", przełącznik "Plan / Kalendarz" (miesięczny kalendarz, drag na inny dzień, "Dzisiaj", Miesiąc/Lista), usuwanie planu z potwierdzeniem. Wrzesień–grudzień → rok start, styczeń–sierpień → rok koniec.
- **Kontekst zastępu**: frekwencja + czas aktywności (bez lokalizacji i pogody — moduł usunięty), styl prowadzenia, samodzielność.
- **Zapis przez AI (MCP)**: narzędzie `zapisz_dane_kompasu` (whitelist pól, sekcje: aktywność, problem, kontekst, zadanie, wiersz planu, aktywność planu rocznego). Dwuetapowy: `confirm:false` → propozycja, `confirm:true` po jednoznacznej zgodzie. Po utworzeniu/edycji aktywności komunikat "Odśwież stronę, aby zobaczyć aktualne dane w Kompasie Zbiórek."
- **Pełny ekran w ChatGPT**: `requestDisplayMode({mode:"fullscreen"})`; `_meta.ui.prefersBorder`; widget wersjonowany skrótem SHA-256 (`workspace-<hash>.html`).
- **Tryb Advanced UI** (skill `/ui`): iteracyjny audyt zmienionego widoku; SEO/Lighthouse pełne tylko na żądanie lub jako bramkę release.

## Architektura

- **Widget**: `kompas-ui-plugin/web` (serwowany statycznie z `web/dist`), logika w `web/src/static-app-v2.js`.
- **Worker `wtyczka-rr`**: `kompas-ui-plugin/cloudflare-worker`; serwuje UI, proxy katalogów, MCP zapis.
- **Cache katalogów**: Worker proxy `GET /api/activities` (baza zabaw, świeżość 1 h / awaria 6 h) i `GET /api/skills` (świeżość 6 h / awaria 24 h) w `caches.default`; dodatkowa kopia w IndexedDB (`kompas-catalog-v1`, TTL odpowiednio 6 h / 24 h). Nie synchronizuje się między urządzeniami.
- **Serwer MCP**: `kompas-ui-plugin/server`.
- **Registry UI `@kompas`**: source of truth to `registry/kompas/`, composed by root `registry.json`. `C:\paperclip\start-paperclip.cmd` starts `scripts/ui-registry/shadcn-registry-server.mjs`, which exposes one valid Streamable HTTP MCP endpoint: `http://127.0.0.1:4173/mcp`. Use this exact URL for the `shadcn` app in Paperclip, without a key. The same process serves built artifacts on `http://127.0.0.1:4173/r/<item>.json`. It provides `list_kompas_components`, `get_kompas_component`, and the `registry://kompas/catalog.json` resource. Search and inspect with `@kompas/<item>`, then preview installation with `pnpm exec shadcn add @kompas/<item> --dry-run --yes`.
- **Promocja UI**: `pnpm ui:promote -- --name <kebab-case> --type <ui|component|block|shell|page> --source <repo-path> --title <title> --description <description>`. The workflow rejects naming and source collisions, writes the item definition and source into the correct `registry/kompas` category, validates and builds the registry, builds Storybook, typechecks both app targets, builds and tests the widget, dry-runs installation in an isolated consumer and runs Playwright. `page` also requires `--target`.
- **Migrated registry runtime**: `kompas-button`, `kompas-input`, `kompas-card`, `kompas-badge`, `kompas-tabs`, `kompas-dialog`, `kompas-typography`, `kompas-brand-tokens`, `brand-header`, `stage-checklist` and `app-shell` are live source modules consumed by `web/scripts/build-static.mjs`; `kompas-brand-tokens` is promoted from kanonicznych tokenów marki v48 (forest/paper/red/gold, Noto Sans Display, rytm 4 px, radius 8/999/50%, motion .16s, shell 1280). Kanon wizualny to wygląd produkcyjny `panel.kompaszbiorek.pl/ui` (v48), drugorzędnie `kompas-ui-design/INSTRUKCJE-BRANDINGU-AI.md`. Aplikacja (`web/src/styles.css`) jest zunifikowana na tokenach v48; off-brand wyspa `.skill-archive` (teal #173239) ztokenizowana do `var(--forest-950)/paper-2/line/gold/red` i usunięte duplikaty. Dashboard: karty `dashboard-card` radius 8 + cień 0 2px 18px, `nearest-card` radius 8 + cień, `cycle-card`/`todo-card` top-accent gold 3 px, poprawiony responsive overflow (375/768/1024/1440 — task-editor wrap). Static runtime dependencies are explicitly recorded in registry metadata and must not be installed as generic React components.
- **Storybook katalog**: `Storybook 10.5.10` działa jako `@storybook/html-vite` na `http://127.0.0.1:6006` i jest uruchamiany idempotentnie przez `C:\paperclip\start-paperclip.cmd`. Konfiguracja `.storybook/` ładuje ten sam CSS aplikacji i wykrywa wyłącznie stories obok source registry (`registry/kompas/**/*.stories.js`). Obecne stories (11 items): Foundations/Tokeny marki + Typografia, UI/Przycisk, Input (input/textarea/select), Karta, Odznaka, Zakładki, Dialog, Components/Nagłówek marki, Blocks/Checklista etapów oraz Shells/App shell; każdy dokumentuje Default/Hover/Disabled/Empty/Long content oraz 375/768/1024/1440.
- **Storybook e-maili**: osobna kategoria `Kompas/E-maile/Onboarding` agreguje pięć istniejących szablonów z `onboarding-emails/html/` w izolowanych iframe. Stories są podglądem źródłowego HTML, nie wysyłają wiadomości i nie zmieniają konfiguracji Sender.net.
- **Storybook MCP**: oficjalny `@storybook/addon-mcp@0.7.0` wystawia streamingowy MCP `http://127.0.0.1:6006/mcp` jako `kompas-storybook` w `opencode.json`. Endpoint jest dostępny, gdy osobno działa Storybook. Oferuje discovery stories, source-to-story mapę i preview URLs. `ui:promote` buduje Storybook, a dla nowego wizualnego pliku `.js` utworzy story skeleton wyłącznie przy jawnych `--story-render` i `--story-args`.
- **Walidacja i wdrożenie registry**: `pnpm ui:promote` przeszedł dla `kompas-brand-tokens` (registry validate/build, Storybook build, typecheck, widget build, isolated dry-run, 8 testów responsive). Workery wdrożono: `wtyczka-rr` `6cfb435c-2854-40bc-85cd-e265b7e7a783`, `panel-kompaszbiorek` `e2fd0b2c-f934-4c70-bb34-fb82b4d28107`.
- **Publiczny MCP Paperclip**: `C:\paperclip\mcp-public-gateway.mjs` — OAuth gateway na porcie 3103, wystawiany przez `https://mcp.kompaszbiorek.pl/mcp`; agregat publiczny zawiera wyłącznie Paperclip i serwuje domyślnie 17 narzędzi operatora. Gateway serwuje rozszerzenie skills (SEP-2640 subset OpenAI): `capabilities.extensions["io.modelcontextprotocol/skills"]` w `initialize`, `skills/list`, `skills/get` i `resources/read` dla pięciu operator skills z `C:\paperclip\skills\` (digesty SHA-256, pełna treść dopiero przez `resources/read`). Po zmianie skilli wymagany restart lokalnego gatewaya i ponowny Scan Tools w portalu pluginu. Stary `paperclip-mcp/public-mcp-proxy.mjs` pozostaje osobnym legacy endpointem.
- **Zdalny MCP OpenCode CTB**: `opencode-mcp/ctb-gateway.mjs` jest publicznym gatewayem Streamable HTTP na porcie `4097`, wystawianym przez tunel Cloudflare jako `https://opencode.kompaszbiorek.pl/mcp`. Engine jest pinowanym submodulem `AlaeddineMessadi/opencode-mcp` (`4e4db4c`, v1.11.0): 80 narzędzi, 10 resources i 6 prompts. Gateway nie duplikuje API upstreamu: przekazuje jego metody, dodając wyłącznie OAuth 2.1, klasyfikację `READ`/`SESSION_CONTROL`/`WRITE`/`PRIVILEGED_WRITE`/`ADMIN`, izolację katalogu, CTB envelope, audit, lokalną korelację runu i discovery sześciu skills CTB. Scopes: `opencode:read`, `opencode:session`, `opencode:ctb:execute`, `opencode:admin`; compatibility alias `opencode:write` jest honorowany przez policy. Każdy write wymaga `ctb.mode=EXECUTE`, `ctb.changeClass=ctb`, `paperclipIssueId`, `changeIntent`, `scope`, `acceptanceCriteria` i `idempotencyKey`; bez nich zwraca `CTB_EXECUTION_CONTEXT_REQUIRED`, a request bez klasyfikacji `CTB_INTAKE_REQUIRED` (szczegóły: wpis „CTB intake i korelacja v2" poniżej). `PAPERCLIP_SERVICE_TOKEN` i `PAPERCLIP_API_URL` są wymagane do faktycznej walidacji issue przed EXECUTE, więc brak tych sekretów blokuje write bez bypassu. Uruchomienie: `powershell -ExecutionPolicy Bypass -File .\opencode-mcp\start-opencode-mcp.ps1`; launcher rozpoznaje i wymienia dawny 9-tool gateway. Test protokołu: `node .\opencode-mcp\test-mcp.mjs`; upstream i procedura synchronizacji: `opencode-mcp/UPSTREAM.md`.
- **CTB intake i korelacja v2**: gateway przyjmuje `mode=DIAGNOSE|PLAN|EXECUTE` oraz `changeClass=ctb|itb|rtb|product`. `DIAGNOSE` i `PLAN` mają pełny powierzchniowy dostęp obserwacyjny `READ` bez mutacji `ctb-runs.json`. ITB i RTB zwracają `HANDOFF_TO=Paperclip`, a product `HANDOFF_TO=PRODUCT_DELIVERY`, zanim gateway zażąda envelope CTB. `EXECUTE+ctb` wymaga jawnego `executionContext.sessionId` albo przekazanego `sessionId`/`id`; gateway nie analizuje odpowiedzi narzędzia ani SSE w poszukiwaniu `ses_*`. Paperclip autoryzuje firmę, lifecycle `todo|in_progress`, dokładny `currentExecutionWorkspace.cwd` oraz jawne metadata `executionPolicy.ctb` lub `metadata.ctb`: `changeClass:"ctb"`, `projectRoots`, `changeIntents`, `acceptanceCriteria`. Wszystkie trzy scope lists są porównywane exact; brak potwierdzenia kończy się `CTB_ISSUE_SCOPE_MISMATCH`. Klucz `(companyId,paperclipIssueId,idempotencyKey)` zwraca ten sam running/completed run, a failed run wymaga `ctb.retry=true`. Decyzja policy jest utrwalana przy runie. Natywne `skills/list` i `skills/get` obsługują reklamowane rozszerzenie `io.modelcontextprotocol/skills`; compatibility tools pozostają dostępne. Testy: `node opencode-mcp/test-ctb-policy.mjs`, `node opencode-mcp/test-run-identity-regression.mjs`, `OPENCODE_CTB_TEST_URL=http://127.0.0.1:4097 node opencode-mcp/test-ctb-mcp.mjs`.

- **Analityka runów (read-only)**: `opencode-mcp/run-analytics.mjs` + osiem narzędzi MCP w gatewayu CTB: `paperclipGetRunMetrics`, `paperclipGetRunEvents`, `paperclipGetRunTokenUsage`, `paperclipGetRunSteps`, `paperclipGetRunContextBreakdown`, `paperclipGetRunModelTurns`, `paperclipCompareRunMetrics`, `paperclipAggregateRunMetrics` (scope `opencode:read`, `readOnlyHint`). Źródła danych: metadata wiadomości sesji OpenCode (`info.tokens`, `providerID/modelID`, części `step-start`/`step-finish`, tool parts), limity modeli z `/config/providers` oraz rejestr korelacji CTB. Tokeny input/output/cache są `provider_reported`; okno kontekstu i wykorzystanie `opencode_reported`; sekcje breakdownu system/role/wake/tool-schema/continuation są jawnie `null` z `measurementSource:"unavailable"` (brak ekspozycji po stronie OpenCode — brak zgadywania); task/history/toolResult są liczone lokalnie (`locally_tokenized`, estymator ~4 znaki/token). Klasyfikacja invocations: `fresh_invocation|continuation_same_session|reconstructed_continuation|retry_after_failure` na bazie sygnałów (asystent przed startem runu, eventy błędów `PROCESS_LOST/PROVIDER/ENGINE_EXITED`, checkpoint Paperclip). `supportedObservability` nigdy nie zwraca `true` bez danych. Porównanie runów wskazuje większy context overhead przez udokumentowany proxy `nonTaskInputTokens = input − task − toolResults` (upper bound; exact overhead nieosiągalny). Po EXECUTE do rejestru trwale zapisywane są zdarzenia `model_turn` z pełnym event modelem (turnIndex, tokeny, measurementSource). Agregaty: total turns/steps/tokens, tokens per successful task, retries per successful task, first-pass success rate, avg context utilization, p50/p95 time to first useful action. Testy: `node opencode-mcp/test-run-analytics.mjs` (scenariusze: prosty inference, shell/file read, MCP tool, continuation, provider failure) oraz blok „Run analytics read-only surface" w `node opencode-mcp/test-ctb-mcp.mjs`.

## Paperclip operator commands

- **Full skills**: `C:\paperclip\skills\paperclip-debug-run\SKILL.md`, `paperclip-napraw-tools`, `paperclip-opencode-health`, `paperclip-deleguj-coo`, `paperclip-wdroz-runtime`. Paperclip imports these into the existing company skill library and exposes metadata first; full content is loaded on demand.
- **OpenCode wrappers**: `C:\paperclip\.opencode\commands\` contains only five short wrappers. The project-local mirror is in `.opencode/commands/` so manual OpenCode sessions expose the same `/paperclip-*` commands. Each wrapper forwards `$ARGUMENTS` and loads exactly one skill.
- **Runtime isolation**: the Paperclip OpenCode adapter injects only the allowlisted wrappers into the generated runtime config. Host commands, host MCP, host plugins, host agents, and host skills are not inherited.
- **Assignment**: the main operator receives all five skills; COO receives `paperclip-deleguj-coo`; Engineer is not assigned all five automatically.
- **Commands**: `/paperclip-debug-run`, `/paperclip-napraw-tools`, `/paperclip-opencode-health`, `/paperclip-deleguj-coo`, `/paperclip-wdroz-runtime`. The obsolete `chatgpt-cli-handoff` command is not implemented.
- **Tests**: `npm run test:operator-commands` in `C:\paperclip`; adapter isolation tests include generated command config and argument forwarding. OpenAI imports a static skill snapshot, so run Scan Tools again after content changes.
