# Mascots STYLE_2 — deterministic SVG → PNG pipeline

Canonical root: `assets/mascots/style-2/<character>/`. One source of truth per
character, one renderer, no duplicate SSOT.

Compositions live in `assets/mascots/style-2/scenes/<scene>/` with `source.svg`
and `scene.json` (`id`, optional `minimumComponentShare`, default `0.01`). They
use the same SVG validation, renderer, PNG pixel checks, hashes and
manifest pipeline, but do not use `character.json` or the character-only
five-color / single-character-component rules. Each scene component must meet
its minimum share of total opaque pixels at every export size after components
below 1% of the largest component are treated as raster noise. Scenes may
contain multiple co-characters and intentionally crop to their source viewBox;
they are not expanded by the character safe margin and may touch the canvas
edge. Export dimensions are recorded as width and height, preserving the
source viewBox aspect ratio.

**Art sources are the Designer's real masters** (KOMAA-1010, commit `c411faa`):
`iskra/source.svg` + `iskra/character.json` and `szlif/source.svg` +
`szlif/character.json`. Every PNG in this tree is *always* generated by this
pipeline — the Designer branch's own sharp-rendered PNGs, set manifest and
silhouette renders were dropped on purpose, so no renderer can drift from the
master and nothing shipped here is an unverifiable copy.
Independent UI QA **passed** the art on candidate `c411faa` (KOMAA-1010,
2026-10-19). `qa.json` and `character.json` keep the Designer's self-QA
snapshot from that candidate, so `qaVerdict: designer-pass-pending-uiqa` is the
historical self-QA state, not the current review state. A later Designer
amendment only replaces the source SVGs; the pipeline is then re-run.

## Layout

Per character (`iskra/`, `szlif/`):

- `source.svg` — editable master (grouped semantic ids)
- `character.json` — metadata (`id`, `species`, `role`, `styleVersion`, `palette`, …)
- `exports/export-{512,256,128,64,32}.png` — transparent renders (committed, reviewable)
- `exports/manifest.json` — source/output SHA256, renderer versions, per-size stats, bbox
- `exports/contact-sheet.png` — horizontal strip of the five sizes

At the root:

- `manifest.json` — set index: characters, scenes, source/export hashes, per-asset manifest hashes, optional silhouette source + export hashes
- `contact-sheet.png` — set sheet (rows 256/128/64/32, one column per asset)
- `silhouettes/` — design artifacts (the 6 sketch SVGs) plus the pipeline's own
  renders: `silhouettes/png/*-{512,256,128,64,32}.png` and `silhouettes/sheet.png`
- `PROVENANCE.md`, `qa.json` — Design artifacts (not renderer output)
- `../../../../docs/mascots/style-2-character-bible.md` — Character Bible (token source)

## Install / run

```sh
npm install --include=dev   # NOTE: plain `npm install` skips devDeps when NODE_ENV=production
npm run mascots              # validate + render + verify all characters (exit 0 = PASS)
node scripts/mascots/export.mjs --character iskra   # single character
node --test tests/mascot-pipeline.test.mjs           # pipeline tests
```

The CLI validates `character.json` or `scene.json` and rejects unsafe SVG input
(`<!ENTITY>`, `<script>`, `<foreignObject>`, event handlers, remote refs),
renders via `@resvg/resvg-js`, then verifies each PNG: target width and recorded
aspect-preserving height,
transparent background, non-blank pixels, content fully inside the canvas
(clipping check), and records SHA256. Any failure — including a missing
output file — exits non-zero. Output is byte-reproducible across runs.

Masters are rendered inside a 4% safe margin (`SAFE_MARGIN`): downscale
rounding clips art that sits within a pixel of the viewBox edge (real case:
Szlif at 32px), so the render — never the committed master — is expanded.
`manifest.json` records the margin used for every export.
